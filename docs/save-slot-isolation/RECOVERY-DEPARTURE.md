# Private recovery departure

Generic `SaveSession.flush` cannot preserve local progress while a recovery owner enforces its write barrier: ordinary writes refuse, then flush closes the session. The new fixture reproduces that loss of opportunity before exercising the separate departure path. No production source or real save changed.

`RecoveryDeparturePrototype` seals the existing enforced baseline scope. It closes session intake synchronously, so the actual session's progress/life messages, load, worker and generic flush stop. Already-issued requests drain before a final local snapshot or another request. Closing invalidates recovery fences; the owner is cancelled after drain. The write barrier remains enforced throughout and is never reopened.

The departure capability touches only the same owner's P key through the pinned provider. One UpdateAsync recomputes the pure three-way merge against the callback's current supported primary and atomically removes this exact session's fresh lease. It preserves genuine local changes and monotonic history without replaying unchanged stale settings. Covered progress only removes lock metadata; payload, timestamp, checksum and backup remain unchanged. R, M1 and all A1 archives are untouched. The recovery packet's 32K progress bound preserves legal histories larger than the old 16K message limit; over-capacity unions refuse rather than trim.

An uncached readback must match the final callback candidate exactly before the result says progress preserved and lease released. Lost write acknowledgements therefore do not trigger blind duplicate writes. A failed write may retry only after an uncached read still shows this session's fresh lease. Foreign, stale, future-dated, corrupt, newer, unsupported, replaced-provider or changed-session observations refuse. A newly arrived owner after a release makes the readback ambiguous; this path reports unverified and never overwrites the arrival. Unverified does not mean the earlier write failed.

There are at most eight charged requests in 24 seconds, one per step, with bounded retry backoff. Departure can exceed the rolling gameplay allowance, as the existing flush already allows, but every request is recorded. A provider call cannot be preempted: after a deadline, callbacks that have not committed refuse and late acknowledgements cannot establish success. On refusal the session stays closed and ordinary writes stay blocked; an unverified remote lock expires normally. The path handles a pending, cancelled or refused recovery owner with no queued rest/life work. It explicitly refuses queued work instead of dropping it.

## Still required before adoption

This is a recovery-only **private departure path**, not completed production lifecycle integration. Route server departure/shutdown to it only when the recovery owner exists; leave normal healthy sessions' rest flush intact. Complete terminal-held idle heartbeat/expiry and safe session replacement, production factory/tick/menu routing and schema-3 entry. Pending unrelated rest/life work needs an explicit integration policy. Native coroutine/provider checks, actual Roblox service interruption/rejoin and durable schema-3 readers/writers remain open. No gameplay credential, migration-complete, release, phone-performance or publication claim follows from these tests.
