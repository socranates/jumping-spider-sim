# Private archive publication and fresh reads

Based on405e9df; not connected to production. Publication passes272 CLI assertions, fresh/raw reads32, and the combined server-context Roblox test304 with all226 source fingerprints and zero CreatorErrors. The current combined compile/full strict proof is fresh-read-types.json. Earlier store-only type receipts retain their earlier source hashes. verify-recovery-store.py checks the current candidate bytes, logs, native source manifest and closed/restored diagnostic.

The repository writes only five bounded A1_owner_* archive keys. Its first write contains both the original progress value and the complete source matrix. It then writes/verifies the other three slots; the completion marker is last. Each step makes at most one backend request, allowing the future server scheduler to apply request budgets and backoff. The publisher also checks the actual aggregate size of all five artifacts, including the duplicated recovery matrix. It does not touch P_/R_ source keys, start a new life, grant an authority credential or apply a world.

Already matching values are verified rather than rewritten. Different/unknown values refuse without replacement. Lost write acknowledgements require readback; read failure remains retryable, not success. An interrupted archive can reconstruct its immutable plan from the first recovery record, existing parts and matching original raw reads for missing parts. It retains the original progress observation even if current lock metadata advanced. Missing/unread or changed original parts refuse. A completed archive can be verified without any original source reads. This is a fixed, bounded one-archive-per-owner namespace; changing original observations and lifetime/retention policy still need the integrating controller's explicit treatment.

All write callbacks and reads check a caller-supplied synchronous authority/source fence. The plan is copied/frozen before a backend can yield. Tests cover callback retries, ambiguous before/after-write failures, conflicting values, bad readback, concurrent publishers, cancellation and genuine coroutine suspension during requests, including cancellation of the final acknowledgement. These tests prove the private protocol under the backend contract; the real SaveSession lease/life/intent fence is not implemented by a callback that merely returns true in a fixture.

The cache boundary matters. Roblox documents a four-second local GetAsync cache and recommends UseCache=false for verification after uncertain writes. The private backend adds readFresh (uncached, preserving ordinary codec behavior) and readRawFresh (uncached and before decoding/backup substitution), while leaving ordinary read unchanged. Temporary DataStoreGetOptions instances are destroyed on success and error; the native test checks actual engine objects. See [Roblox's caching and verification guidance](https://create.roblox.com/docs/cloud-services/data-stores/versioning-listing-and-caching).

The publisher now requires an explicit readFresh method, so the production adapter's older cached read cannot silently satisfy readback. MemoryBackend fixtures explicitly expose their inherently uncached reads. A fake cached store reproduces stale data after a lost acknowledgement and a cache hiding damaged archive data; the fresh path resolves/refuses those correctly. No real DataStore service was contacted by these tests.

Remaining work: integrate server-owned uncached raw collection, request/byte quotas and backoff, actual SaveSession authority/source checks, portable progress projection, destination/checkpoint schema and atomic commit, real isolated DataStore/rejoin tests and release gates. Ordinary production DataStoreBackend.read and SaveSession call sites remain unchanged. Their existing ambiguous-write/intent-validation paths need a separate cache-aware integration audit; no live failure or production fix is claimed here.
