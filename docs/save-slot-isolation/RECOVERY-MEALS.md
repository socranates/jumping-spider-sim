# Private portable reserves and meal history

This is a projection dependency, not complete progress import. `recovery-meals-prototype.luau` prepares an owned, frozen portable capsule from the privately inspected source graph. It exports only NeedsModel and Feeding, their shared reserve reference and the exact `life.grantedSeen` food cursor. It does not export the old prey population, garden, coordinates, perception, life clock, growth object or mating state, and does not edit any source or live destination. Those remaining components still require their own explicit mapping.

## Field policy

All supported NeedsModel fields are copied, including reserves, elapsed/accumulated time, complete energy books, grant counters, starvation hours/streak, gentle/life switches and survival/movement pacing. The sole excluded field is `onEnergyChanged`, a program callback: the future destination must reconnect its own callback. It is not serialized as historical progress. Unknown fields refuse rather than being silently discarded.

All supported Feeding fields are copied, including nutrition taken, energy granted, the full feeding book, completed meals, settings, struggle parameters and its independent random stream. Feeding must have no held prey and must be neither struggling nor eating. This prototype does not turn an in-progress meal into a completed one. Its reserve pointer is rewired to the capsule's single owned NeedsModel. Random streams accept only their known state field; an unexpected reference to an old world refuses. The reserve and feeding ledgers must remain separate objects. `recovery-meals-fields.json` enumerates each supported field and action.

Both historical energy books receive the same injective key mapping: `@archive/<server archive identity>/<entire original key>`. Original key bytes are retained after the fixed prefix, including keys that already contain delimiters or a previous archive prefix. Values, totals, nutrition taken, meal counts and growth cursor remain exact. The untouched complete source archive remains the original-key record. Calling prepare again on the same inspected source and archive identity gives the same capsule; this does not replace the future destination transaction's idempotence rules.

The namespace separates old food from current capture keys such as `fly_1:1` and the aggregate `rival_spider_meal` key. Current authored prey prefixes do not use `@archive/`. A full destination builder must enforce that namespace separation for every present and later streamed director; it must not assume this helper changes spawning or existing capture code. No fly, feeding or settings production code was edited. Historical grants are not turned into fresh food: the caller preserves the exact grantedSeen cursor alongside the later growth mapping.

The capsule is an internal preparation result. Its decode method checks the restricted object classes, graph identities, fields, books and namespace. It is not a new remote/storage boundary: the integrating caller must enforce aggregate character/node/entry bounds before accepting a transported object and before creating the complete destination checkpoint. This helper's Work pulse points support cooperative preparation but are not a hard native frame-time or memory bound. The source must remain private and stable while a worker runs.
