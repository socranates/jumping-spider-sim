Measurement definitions:

- Payload: a copy of the first actual message for each direction/kind/mode key; canonical JSON bytes computed after the run. This is a representative logical size, **not Roblox wire size**, compression ratio, total traffic or per-message distribution. Copy overhead is recorded separately and remains inside overall elapsed time.
- Delivery: server timestamp immediately before the actual FireClient and client timestamp at the start of its actual OnClientEvent callback, paired by epoch/sequence/kind. GetServerTimeNow clock estimates and local Studio scheduling affect this difference; it is not Internet latency or RTT. Negative samples are retained. The deliberately replayed old grant is excluded because it has no new observed server-send timestamp.
- Client calls: os.clock wall duration around each synchronous application/entry/save-client update. Application contains entry work, so **do not add nested totals**. Maxima include native calls, collection and observer overhead where applicable; they are not process CPU accounting or hard slice guarantees.
- Heartbeat: observed frame intervals grouped by current application/entry/slot phase. They include the whole engine, render work, synthetic snapshots and this diagnostic. These are not representative gameplay FPS or proof of a rendering bottleneck.
- Provider: wall duration of each injected memory read/update, including its deliberate0.01-second yielding wait. No real DataStore latency, quota or availability inference is supported.
- Marks: actual-clock spans from Main Continue choice to applied adoption, applied-ACK release to playing, and each mode's normal checkpoint preparation/stored acknowledgement. The release mark precedes the diagnostic inspect request; that span includes its snapshot/return. Protocol timing remains accelerated10x, and real seconds must never be relabeled as production-clock or online load time.
