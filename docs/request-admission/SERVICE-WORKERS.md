# Private account-service admission

This candidate connects [the ordinary/Profile cohort](PROFILE-WORKERS.md) to the actual SaveService and negotiated replacement adapters. One explicitly supplied server-owned AccountLifetimes instance owns the shared Gate and every physical-account visit. It is still private: normal engine startup, native/online qualification and release are not installed or proved by these CLI tests.

## Construction, debt and identity

ReplacementService obtains a fresh scope before calling its trusted unloaded-owner factory. It supplies the lane in the Session config, preserving the original physical key through replacement. Accounts validates the exact Session ID, user, backend/source binding, scheduler, counters and lane before wrapping load/flush. Old startup scheduler wrappers are refused at construction and cleanup boundaries. The existing Runtime/Profile child propagation supplies the same lane to all initial, ordinary, discovery, archive, commit, entry, saving, New, held and departure work.

Complete supplied unknown history is conservatively imported as read+write before any provider request. Failed construction retains it; replacement reuses the Gate's physical ledger without reimporting, resetting or copying an old aggregate scheduler allowance. A constructor cancelled during history lookup still imports the complete returned known history before closing. Oversized history is refused, never truncated. Closed registry diagnostics may be discarded because the Gate independently retains recent debt and actually started calls. Active registry size is bounded by Gate capacity.

The dependency contract is cold initialization or an already-quiesced legacy boundary with complete supplied account history. This is not an arbitrary hot-swap mechanism while untracked old providers are still active. Never install a partial set or leave old startup wrappers running beside it. The limits in these tests are fixture configuration, not a Roblox policy.

## Leaving during initial load

SaveService calls the owner cancellation hook even when addPlayer already returned and its load task has not started. Cancellation closes intake and invalidates the load serial, including the previously uninitialized serial case. OrdinaryRequestAdmission stops queued work but never manually resumes a provider or timer. An actual started call must drain before cleanup or another account epoch; committed storage and request debt are retained.

Closed cleanup cannot reopen the Session, grant a life or replay player data. It captures only that visit's progress key and physical updater, checks schema/ownership, clears only its own lock and verifies with a fresh raw read. The real DataStoreBackend has no updateRaw method: its existing update method preserves P envelopes without the R codec, so the closed scope binds that P updater plus readRawFresh and rejects every other key. Payload, checksum, backup, R records, archives and proposals remain untouched. A foreign lock is never cleared. An ambiguous cleanup response gets a fresh probe before another write.

Cleanup has at most6 starts and the existing flush deadline. Capacity waits spend no provider attempt/failure/backoff; real failures retain existing backoff. If cleanup cannot verify release by the deadline, it reports failure and preserves the uncertain stored lock. A rejoin cannot steal it. Shutdown revokes remaining scopes, retains started calls until actual drain and discards late results; it does not fabricate cleanup after its deadline. Both completed and failed flush paths close old intake. Source/counter/scheduler/config routing changes refuse cleanup.

## Replacement and dispatch

The actual old-owner closed-departure proof still precedes replacement commit/ready. Only then can the service open a distinct epoch on the same account Gate. Typed replacement bypasses the old64-entry scheduler copy and its reserved aggregate load quota; inheritReplacementDebt explicitly refuses typed owners. The direct Runtime replacement shortcut remains guarded: the negotiated service route owns epoch construction. Lost packets and late old-epoch messages cannot create extra owners or grants.

The service queues at most one step task per entry and skips redundant tasks while a native-style ordinary provider is busy. Another account can still run an eligible read while a write waits. A failed task launch releases its dispatch slot; failure before the initial task starts closes the unloaded owner without I/O and balances departure accounting. This is bounded-dispatch evidence, not a measured native CPU/FPS improvement.

An additional probe reproduced an initial-load hang: a request ticket expired after120 seconds of no allowance, with zero provider starts, but the owner stayed loading and could not retry. The same still-owned routing scope now demotes to retryable session-only status without inventing a provider failure. Load serial, backend, config, counters, scheduler, lane and original scheduler methods must still match; the existing startup-wrapper refusal remains intact. Allowance restoration then loads exact records on the same lane. A separate repeated-outage probe passed on its first attempt: polled load retries already retained session/canRetry, including an expired coroutine context. That was verification of existing behavior, not a second reproduced defect or additional fix.
