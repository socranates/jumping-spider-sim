# Private recovery guard against actual save-session state

The private raw collector now composes with a guard that inspects the actual SaveSession, SaveIntent and SaveObservation objects. Nothing is connected to production and no save key, schema, world or life credential is changed by the guard.

Admission requires an active session with a recently acknowledged local lease, no running session worker, and an exact selected Continue request that is still read-only. The guard captures the session/load generation, backend, scheduler, owner/key identity, request reference/revision, selection identity and protection status. It refuses pending destination/life work. Checks before and after yielding reject departure, demotion, reload, request supersession, credential grants, changed selections, replaced backends, expired observations and backwards/failed clocks. Once a check fails the ticket stays revoked, even after a later heartbeat. The original draft failed this last condition; the negative run retains the precise counterexample. No retry may resurrect an old ticket.

Repeated checks inspect only bounded server-owned metadata. They do not call the public selection API, which copies a complete checkpoint. This relies explicitly on the current internal SaveObservation.choices shape; current runtime bundle fingerprint verification binds that dependency. The fence has no client-facing entry point. A future integrating controller must serialize its work with SaveSession; this module alone does not claim exclusive worker ownership.

After the raw collector finishes, matchesPlan compares its raw progress lock/session/age and the selected primary or backup envelope identity, including persisted life. The collection fixture uses a real checkpoint and a real Continue selection, including a corrupt current envelope with a readable backup. The raw envelope remains unchanged. This bounded identity comparison is not checkpoint validation, authentication or authority to write a destination. The caller must use the validated, frozen collector plan, never a client-provided object. Portable projection must independently validate the source content against its schema.

Evidence: 129 CLI assertions, compilation and full strict analysis pass. All 14 invalidation cases run during a genuinely suspended backend read and prevent the result from starting CPU preparation or exposing an archive plan. Real SaveSession public load/demote/request methods and real intent/observation methods are used where applicable; closed/backend/clock faults are injected directly. The initial draft passes 112 earlier checks but fails the stronger expired-ticket resurrection test; both its source and failure are retained. verify-recovery-session-fence.py reconstructs the executed bundles from current runtime dependencies and validates the hashes, positive/negative outputs and type-analysis receipts.

MemoryBackend does not prove actual remote ownership. Another server can acquire a lease after a raw read; no local guard can atomically fence five archive keys and a destination key with a separate progress lease. Immutable archive writes must remain harmless when ownership is lost, and destination preparation needs a separately designed atomic/serialized commit protocol. Still required: the real server controller with heartbeat/request/backoff/byte scheduling, archive reuse and lifetime policy, portable progress mapping into fresh Preserve ecology, destination schema/commit, native and real isolated service/rejoin checks, and release verification. This guard is a concrete dependency, not completed migration or a production safety claim.
