## Server and platform rules

- **Solo servers first:** publish with maximum players = 1, giving each player a separate server/windowsill. This is the chosen initial architecture; no shared play is authorized in this chunk. Current client-only spider is prototype state, not authoritative multiplayer. Publication settings have **not** been configured by this local build. ROBLOX-40 records the accepted solo-save boundary: server validates client record shape and consistency; it does not claim authoritative gameplay or anti-cheat.
- No custom typed text exists yet. Any future spider name or other player text must be filtered on the server with TextService and the correct recipient/broadcast result before display or reuse. Built-in chat uses Roblox's chat system; do not replace it with a raw echo.
- Saves use DataStoreService, not client files. Do not enable production Studio API access to test saves.
- Keep anchored parts moved with BulkMoveTo. The Studio test and tests/look.luau cap the rig's parts other than hairs and fur shells at 160 and its hairs and shells at 720; the rig has 624 parts at full detail (tests/look.luau caps the total at 705) and 266 in the low tier that touch-only devices get (capped at 272 there, 300 in the Studio test), and the decor is 76 parts at full and 34 at low. These are budget checks, not a mobile-performance pass. Measure frame intervals on a real low-end phone/tablet with settings/device recorded, without screenshot stalls; report median/p95/worst and warm-up separately. Reduce decoration/postprocessing based on evidence.

## Testing workflow

From `roblox_port/`, run `python tests/run.py path/to/luau` (Luau 0.742 used here). It prints six lines. SUMMARY: pure logic and Godot goldens (182/182 on branch claude/roblox-controls-recovery; the original 35 jump/support checks use the Godot-exported `tests/jump_reference.json`). BOXWORLD: `tests/studio/RecoveryScenarios.luau` and Chet's silk spec on an emulation of raycasts and sphere casts against axis-aligned boxes (15/15), a smoke test of the real motor, silk and camera code, never engine evidence. CLIENT: the client scripts themselves with stub services (11/11). LOOK (`tests/look.luau`, 72/72): the real rig, Anatomy, Setae and Idle under the shim, with the daughter's pattern pinned, the look knobs, the coat (short, thin, lying flat and combed toward the rear; white hairs wholly inside the drawn markings, black hairs clear of them and of the cheeks), bounded idle motion and the part budgets at full and low detail. WORLD (`tests/world.luau`, 71/71): the real graphics table, materials, sun pick, scenery, lighting set-up and low-detail tier with an invented sun. Neither says how anything looks in Roblox. PERCEPTION (`tests/perception.luau`, 4669/4669): the perception modules (`src/Shared/Perception/`) against Godot's hand-written unit expectations and against `tests/perception_reference.json`, which `tools/export_perception_reference.gd` makes by driving the frozen Godot modules (math tables, record validity, and 29 scripted sensor scenarios replayed tick by tick: timing, decay, marks, association); the world half of the sensor (rays, gaze) is scripted there, not ported yet. Extend this pattern for each pure module. Export new fixture data from the frozen Godot implementation, record source commit and parameters, and retain both expected decisions and numeric tolerances. Never regenerate expected values from the port under test.

Run `python tools/build.py path/to/rojo` (Rojo 7.7.1 here). It stamps a source/test/project SHA-256 prefix in BuildInfo and rebuilds both places. Open **TheWindowsillTests.rbxlx** in Studio and press Play. `ServerScriptService.PortTests` runs real Vector3, raycasts, parts and BulkMoveTo (Spec, SilkSpec), the recovery scenarios with the real motor and camera on the windowsill's boxes (RecoveryScenarios, ten misses with the camera on each) and prompt wrapping with Roblox's text metrics (PromptSpec), the graphics set-up (GraphicsSpec: Future lighting and 2022 materials, the sun through the window, decor that is drawn only, shadows, effects, dust and shafts), emits `PORT_TEST_REPORT` JSON in Output, and stores it as `TestService.PortTestReport`. The client playback (SilkPlayback) drives the real client through `SpiderInput.simulate`. The count includes a suite-completion check; a missing report is not a pass. Save the JSON with the evidence ID. Normal TheWindowsill.rbxlx excludes the test runner. This lightweight pcall runner is intentionally dependency-free; extend it or adopt TestEZ as suites grow.

Engine-dependent tests run inside Studio on Windows; the plain Luau CLI cannot validate Roblox engine behavior. Linux collaborators can run pure tests. Nathan's PC/tablet playtest covers feel beyond either automated suite. Do not label emulation as physical-device testing.
