# Raw recovery archive preparation prototype

Private only, based on405e9df. The73-check CLI suite, compilation/full strict analysis and82 native assertions pass. All224 native sources were fingerprinted; zero CreatorErrors. Exact source/hash/closure verification passes in verify-recovery-archive.py. No production module, save schema or live save was changed.

A subsequent private [publication protocol and fresh/raw read adapter](RECOVERY-PUBLICATION.md) passes272+32 CLI/304 native assertions plus combined strict analysis. Actual production collection, authority integration, DataStore durability and portable progress import are still pending.

Archive.prepare takes a server-owned owner/observation and exactly four raw read results: progress/main/free/easy. Each must say loaded=true; a physically missing value is recorded as missing, while an unread source refuses the complete plan. The raw values stay opaque: future headers, bad checksums, compression bytes, current/backup cores and unknown payload fields are copied exactly as storable values, without sanitizing, decoding or silently omitting them. Copies and all nested structures are owned/frozen. Source edits afterward cannot change the plan. Checksums detect accidental changes; they do not authenticate a client or replace lease/intent/life checks.

Important source boundary: DataStoreBackend.read currently decodes R_ values with RestCompression, and backup recovery can substitute a deliberately corrupt current core. That result is useful for Continue but is not the complete original raw stored value. Actual integration needs a server-only raw read path before either codec/open operation; this prototype has not added that path. Roblox returns stored values, not its internal serialized bytes. Preservation means identical complete storable values and exact opaque strings, not an invented claim about unavailable storage-wire bytes.

Preparation caps each entry at3,900,000 canonical characters, leaves header room below the one-value storage cap, caps the complete plan's artifact budget at12,000,000, and caps traversal at600,000 values/keys and depth24. The manifest reservation is a conservative upper bound. Options can only reduce those bounds. Repeated/cyclic tables, non-finite numbers, non-storable values, malformed shapes, unavailable slots, unknown source fields and over-cap plans refuse without editing originals. Aggregate limits can intentionally refuse a very large multi-slot save; refusal must keep that source intact. Bounds and actual backend serialization still require durable integration tests.

The native test repeats all73 pure cases, checks engine JSON round trips, and archives an actual paused client checkpoint envelope with an independently owned backup. The resulting archive and source canonical values agree, and the actual client checkpoint stays unchanged. This does not prove DataStore readback, actual player recovery, native migration or the full archive/import transaction. The first prepared native package was not run: its synthetic current/backup payloads aliased the same in-memory table, unlike independent raw stored trees. That fixture was corrected before Play; its unrun package/closure is retained separately. Remaining integration is substantial: raw server reads; a bounded immutable durable archive publication/retry protocol; exact source and authority fences; portable state projection into freshly authored Preserve ecology; schema/readback/rejoin; and native recovery/recapture without archive growth or duplicated feeding. The prototype's four A1_owner_slot descriptors are a fixed one-archive-per-owner preparation namespace, not an implemented publisher. Do not overwrite conflicting entries or call Fresh to clear authority. Interrupted/conflicting publication and archive lifetime through later lives/generations must be decided/tested before wiring this to Continue. Original save keys remain protected until durable preservation and atomic destination preparation succeed.
