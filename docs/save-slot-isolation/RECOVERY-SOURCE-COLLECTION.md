# Private raw collection and archive composition

The source collector is not connected to production. It makes one explicit readRawFresh request per network step and owns CPU preparation in cancellable SaveWork jobs. CPU-only steps continue when the request allowance is exhausted. It reads all four original slots before decoding or backup substitution, then reads each again to check the observation. A failed read remains unavailable/retryable; physical nil becomes missing only after a successful raw read. No archive plan is exposed before final bounded preparation.

Owned frozen copies retain future schemas, corrupt-but-storable values, complete current/backup envelopes and unknown fields. Changed content refuses rather than rebasing an earlier observation. The original progress envelope remains exact even when an explicitly configured same-session heartbeat advances during verification. Every other field must match, including unknown fields, checksums, backups and settings. Backwards/foreign metadata refuses. A session name alone is not authority: real SaveSession lease/intent/source fences still need integration. Two-pass per-key verification is not an atomic multi-key DataStore snapshot.

Each backend call and CPU result is fenced before and after yielding. Cancellation, superseding observations and reentrant workers cannot publish stale results or start concurrent requests. Backend errors remain retryable at the same slot. CPU failures/timeouts refuse; cancellation releases preparation and staged source copies. Completed jobs drop duplicate staging buffers after retaining the immutable final plan. Backend read results must remain private/stable while their bounded CPU copy runs. The caller must not abandon a suspended backend thread; cancellation cannot undo a service request already in flight.

An initial aggregate-copy audit reproduced646 retained raw nodes against a configured500-node cap, before final whole-plan rejection. The corrected collector reserves remaining raw-node/entry allowance while copying each slot, rejecting the second large slot with323 retained nodes. Original values remain untouched; nothing is truncated. Final preparation still checks complete-plan character/node/depth bounds, including metadata. Minimal internal observation labels avoid refusing an archive that exactly fits its declared cap. These are modeled object/character bounds, not measured native heap or whole-server performance claims; an incoming service response and final plan preparation also consume memory.
