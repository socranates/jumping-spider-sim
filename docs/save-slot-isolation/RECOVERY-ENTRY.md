# Private schema-3 recovery entry

The private Runtime now has an opt-in entry handshake after successful archive/commit/rebind. Its default remains the enforced read-only `entry_required` gate. Install the server-owned `RecoveryEntryPrototype` as `recovery.entryFactory` to enable `Runtime:enter()`, `entryApplied(message)` and `cancelEntry()`. Production SaveService, SaveClient, remotes and menus do not install it yet.

## Server proof, client application, server grant

Entry pins the actual bound session/load, selected Continue request/revision, backend/provider, scheduler, keys, enforced baseline hold and recovery owner. It freshly reads the immutable M1 proposal, **all five published A1 records**, current R and P. Cooperative preparation rebuilds the complete original archive and compares every published part/index to it, validates the proposal binding and active schema-3 rest, and checks durable original and current rare progress. Both initial import packets and continued checkpoints are supported; ordinary, retired, ended, mismatched or corrupt data do not enter the active path.

The prepared offer has a new per-runtime entry id plus epoch, slot, intent serial/revision, exact rest identity, scene kind and checkpoint. It contains no new write credential. The client remains paused while `RecoveryEntryClientPrototype.prepare` validates/owns the checkpoint and prepares the actual Checkpoint commit. Preparation may run in SaveWork and changes no live objects. Its single-use commit must run outside preparation with the caller's current selection/epoch guard. It invokes the actual Checkpoint application, preserving rest/mating/hatching state, and returns the narrow `recovery_applied` receipt. A changed selection or failed application returns no receipt. The caller must remain paused until the matching server decision; sending an acknowledgement is not permission to resume or save.

The server accepts only that exact bounded receipt, then reads R and P uncached again. R must still equal the offered raw rest, and P must still have its fresh owned lease and cover proposal/current rare progress. Only then does it call the actual SaveIntent grant and update the per-slot observed identity/life metadata. Runtime installs `recovered` before notifying the decision callback, so a yielding callback cannot later reopen a closed route. No callback or yield occurs inside the grant/metadata commit itself: the existing grant's emitter is temporarily deferred, restored immediately, and notification follows the installed route.

The client simulation is local. Its acknowledgement is a protocol statement, **not anti-cheat proof** that another machine applied the checkpoint. This matches the existing solo game's corruption-safety boundary. A denied final proof leaves the client paused/read-only; it must not keep playing a partially accepted restore or send ordinary schema-2 saves.

## Lifetime and bounds

Entry performs reads only, under at most 24 requests/240 seconds, one request per step and the shared rolling quota. Runtime retains the existing metadata-only lease helper through preparation, client waiting and recovered idle. This helper's renewals use the same session quota; they are separate from the entry job's read cap, and the entry deadline still applies to a waiting client. A normal successful handshake needs eight initial reads and two final reads, plus any independently due lease/probe requests. Transient reads back off; mismatches refuse.

Cancellation drops the offer/preparation and returns to the held entry gate. A retry gets a fresh entry id, so a late receipt cannot apply to it. Changed scope/ownership/clock/deadline, departure or a late provider result cannot grant the old request. Runtime cancels pending entry before its existing closed recovery-departure path. The ordinary progress/rest worker and enforced backend write barrier remain blocked in `recovered`; healthy sessions without opt-in recovery still use their unchanged normal path.

Entry does not write R, A1 or M1. Its prepared result provides the validated original archive/proposal and exact current rest for the separate current writer. The current test composition uses the **real entry-issued credential** with that writer; no manual test grant is needed for the new entry cases. It drives that writer exclusively, then resumes Runtime idle/departure. A full frame-by-frame coordinator for ordinary recovered progress and rest submission is still required before production.

## Evidence

`recovery-entry-verification.json` binds the final `entry-attempt-3-*` cohort and `entry-types-3-*` compile/full strict receipts: **10,322 entry assertions + 51,954 preceding regressions = 62,276 passing assertions**, 30 private candidates strict-clean. Counts include per-step request, quota, busy and permit invariants; they are not 62,276 distinct gameplay scenarios.

Normal, Free and unlocked Easy each exercise rest, mating and hatching: actual discovery/recovery, full archive proof, cooperative client preparation/application, real intent grant, subsequent actual checkpoint capture/current-writer storage, idle lease and closed departure. Further cases cover corrupt archive parts/index/proposal/rest, foreign ownership, request/provider/epoch changes, stale receipts, cancellation/retry, post-application rest/owner changes, clock/deadline/cap refusal, a 100-tick client wait, transient final read, superseded client preparation, late suspended read across closure and a yielded decision callback across departure. No native Roblox transport or real service is used.

The first attempt reached Easy's existing `finished_main` requirement and correctly refused a profile that had not unlocked it. The corrected fixture supplies that durable unlock for Easy only; no production or runtime unlock rule was relaxed. `entry-attempt-1-*` and `entry-types-1-*` are preserved historical evidence. Attempt2 passed before the cleanup change; attempt3 is current. Cancelled/refused entries drop all prepared/archive-read buffers, including when Runtime loses ownership. Successful entries release preparation buffers and share one owned current checkpoint between result and offer instead of retaining duplicate logical/checkpoint graphs. The tests assert this ownership/cleanup structure; no measured heap or FPS reduction is claimed. Earlier individual verifiers pin their older dependency hashes; the final entry cohort is the authoritative proof for the now-modified private Runtime. Production sources/tests are unchanged at `441eaca`.
