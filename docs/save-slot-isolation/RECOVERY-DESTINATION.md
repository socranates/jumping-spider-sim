# Private destination checkpoint assembly

The private builder now assembles a complete checkpoint-shaped Preserve candidate from the portable life capsule and a freshly authored Preserve template. It validates the result with the complete rest/checkpoint checks and returns `status=prepared-only` and `destinationCommitAuthorized=false`. It never changes the live world or writes a save. This is a preparation dependency, not a completed migration, release or playable Continue path.

## Fresh ecology and shared state

The template must be current Preserve geometry with the normal seed, an attached pose in the home retreat, no elapsed life/feeding/capture history, no consumed prey, and no already allocated rare-life serial. The integrating caller must construct it directly under a stable map rather than invoking New Life/Fresh against the player's save or consuming a new global rare roll. The builder refuses a played template. Non-default source simulation seeds require explicit support rather than silently changing the future random schedule.

The imported life and reserves replace only those roots of the privately decoded template. Every loaded regional prey director is rewired to the same imported Feeding, and that Feeding points to the imported NeedsModel. Fresh perches, populations, nutrition, capture serials, ambient creatures and perception roots remain those of the new Preserve. Old Test Garden region entries are never inserted. The builder checks both existing directors and the authored specs for later streamed regions to keep new capture keys outside `@archive/` history.

The new rival is part of the fresh ecology; its full old record remains historical. Mate cycle/courtship state is retained while its pose, orientation, region and route leg come from the current authored mate arrival. Unknown mate fields refuse. Mating scenes and hatching are marked explicitly with an entry kind and `requiresSceneResume`; the builder does not pretend that ordinary rest playback handles those scenes. The actual scene/ending placement, presentation and one-time resume behavior still require client integration and a walkthrough.

Inert `life.recoveryHistory` records the archive identity, original map/life identity, serialized historical actors/skins/encounters and the original entry kind. These are ordinary owned data, not active actor objects or a write credential. Current automatic object-graph capture retains the metadata across subsequent checkpoints, as exercised here. Before production adoption, the protocol/schema review must explicitly validate its shape, bounds, authority binding and lifetime; accepting it as a storable graph alone does not establish those contracts. A second migration still needs an explicit archive-retention/history policy, and the earlier private life mapper intentionally refuses unknown new fields.

Wasp/cat/water counter records are carried forward when present; normal restore already ends their active encounters. Old breakaway geometry stays historical and the fresh template owns the active falling-leaf state. Old skins are not relocated into active growth exuviae. Source life age, reserves, instar, growth credit, generation grace and brood state stay in the imported graph. The global notebook, appearance/settings/progress and RareLedger remain outside this checkpoint and still need projection and transaction binding.

## Verification

The current CLI run passes 71 destination checks, plus all 360 life and 49 meal regressions. The fixture builds actual authored collision regions with WorldBuild.region and populations with production PreyWorld/PreyDirector constructors over the test shim. It includes the home and three populated outdoor regions, six initial outdoor flies, an additional region created later, and full rest validation. This is a selected-region component fixture, not the complete live client, actual network streaming or native geometry/playability proof.

The generated record is also passed to separately loaded, unmodified production Checkpoint and SaveRest validator bodies, with their ordinary active-map behavior. The original historical checkpoint still fails ordinary Continue under the Preserve. The candidate restores, is captured again by production capture, retains historical meal keys and provenance, and passes an isolated MemoryBackend/envelope round trip. Late-created coneflower prey joins the imported feeding/reserve objects. Normal/Easy/Free candidates retain mode, generation grace and guarding state. Courted and hatched candidates retain their stage and carry an explicit mating/hatching entry requirement; these checks do not prove the scenes actually play.

Two early fixture assumptions were wrong: the selected garden cells had no authored prey. Those raw failures and inputs are retained. The fixture now uses the authored milkweed and coneflower sites and compares the actual populated template entries with the result. An initial full strict pass failed on the optional bestiary-list union; the retained diagnostic is corrected with an explicit iteration type. Current compilation/full strict passes with all five private modules. No production source was changed.

`verify-recovery-destination.py` reconstructs the executed bundle, validates hashes for private dependencies and actual production validator inputs, and verifies the current outputs and type-analysis receipts. The tests do not prove native frame time, whole-server memory bounds, durable storage, remote ownership or successful migration of Nathan's actual save. Aggregate size limits and the final ownership/source/intent checks remain mandatory before any destination commit.
