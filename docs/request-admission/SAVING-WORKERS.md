# Typed saving after recovered entry

This extends [the cold recovery pipeline](COMMIT-WORKERS.md) with optional private replacements for routine progress, current-rest writes and the recovered save loop. These files are not installed in normal Runtime/startup. All provider paths must share one service-owned physical-account gate before activation; New, departure, initial load and service lifecycle work remains.

## Behavior preserved

`save-loop.luau` takes a trusted `runtime.recovery.saveOptions.admission` lane. It copies child options, rejects conflicting child lanes and passes the same lane to progress, rest and idle lease owners. Existing ordering remains: captured checkpoint progress must become durable before its rest; later notebook updates cannot indefinitely starve that checkpoint. Progress keeps its per-key debounce, and rests keep their ordered serials and minimum interval. Under typed admission, progress scheduling tests the existing per-key due time directly. Calling the old `SaveScheduler.due()` also applies the obsolete aggregate request cap, so that call remains only in the legacy fallback.

`routine-progress.luau` retains the captured progress reservation, held baseline, fresh lease, bounded merge, raw readback and cooperative local adoption. A queued write retains its callback/evidence without consuming a provider attempt or failure/backoff state. If the player changes a choice while waiting or during an actually yielded write, the latest local choice survives adoption and remains dirty until stored. Ambiguous acknowledgement goes through fresh readback. Refusal/cancellation closes both the operation and lease; unresolved progress provenance remains available to the separate departure protocol.

`current-writer.luau` retains owned capture/preparation, immutable proposal and complete archive comparisons, fresh progress/rare coverage, exact original-or-candidate CAS, raw readback and final fresh ownership witness. It has separate retained ordinary and raw operation handles. Raw writes use a captured `updateRaw` binding to the existing same-store adapter; `session.backend` is never replaced. Waiting for readback does not repeat CAS. A queued phase stays stable through heartbeat scheduling, preventing a retained operation from silently changing its method/key. The original timeout, request cap, retry/backoff and source/intent/credential/life guards remain.

No stored receipt fires until all required reads finish. Cancellation of an already committed raw write cannot roll it back or erase its request debt. Its obsolete result cannot publish a stored receipt. The account gate refuses a replacement epoch until the suspended provider drains.

## Qualification

`saving-qualified-1` passes the complete preceding cohort with these overrides and adds eleven named saving cases: **254680 fixed checks /95 named groups /0**:217320 preceding and37360 saving checks. The complete46-target overlay (45 distinct sources) compiles and is strict-clean in `saving-types-development-2`. `verify-saving.py` reconstructs the current bundle, compares every preceding summary, binds source/type mounts and exact outputs, reconstructs the negative counterexample and checks production against its unchanged committed source. `saving-verification.json` records whether all private inputs are committed. The first development failure was an incorrect test assumption that a first progress change must always wait30 seconds; the actual rule measures the interval from the last successful write. Its exact failed harness is preserved in a hash-checked ZIP, and the final test first stores a change before checking the next interval.

The cases cover Main/Free/Easy using actual Runtime entry, progress and checkpoint data; denial at proposal/write/readback/final witness; latest choices; streaming notebook changes; per-key timing; ambiguous P/R writes; actual suspended progress updates; committed raw-write cancellation/drain; foreign ownership; thrown provider/backoff; caps/deadlines and changed load identity. Admission is enabled only at a quiescent boundary after actual recovered entry. Earlier load/discovery/entry and later departure are not represented as service-wide installations.

`saving-old-due-negative-1` changes exactly the new per-key scheduling block back to the former `SaveScheduler.due()` call. Twelve real extra uncached reads through the same account gate exhaust the old aggregate history. The old call prevents the routine progress job from starting despite available typed capacity. It fails at the intended assertion; the corrected implementation passes the same case. Test limits are explicit fixture configuration, not adopted Roblox capacity values. One thrown-provider case deliberately throws before MemoryBackend increments its own call counter; the provider attempt is nevertheless charged and retained by the gate/session.

These are memory-backed CLI tests with synthetic protocol clocks and the existing private WorldMap/Checkpoint replacements. They do not establish native speed, real-store behavior, FPS, device compatibility or release readiness. Production source/tests remain at bd67582b5d53473f067244fc1e2e1f94adde173b. No main merge or publication.
