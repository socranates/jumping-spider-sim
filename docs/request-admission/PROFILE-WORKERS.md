# Private all-slot Profile admission

The Profile owner must retain the same account lane when it rebuilds recovery dependencies for Main, Free or Easy. Passing a lane into the first Runtime constructor alone is insufficient. This candidate extends [ordinary Session/Runtime admission](ORDINARY-WORKERS.md); account-service lifetime ownership and normal installation remain incomplete.

`profile-options.luau` copies the dependency table and each reader/pipeline/entry/save/progress/rest option table, validates any existing lane, and supplies the same lifecycle lane. `profile-owner.luau` applies it at construction and every profile bind without modifying caller-owned options or changing captured destination templates. It refuses the old startup-budget owner. A pending ordinary request context must drain before rebinding even when admission waiting has released the busy flag.

The profile-switch hold now passes that lane to its lease-only helper. A blocked switch retains its queued request without provider attempts or credentials. Restoring the former missing fourth argument demonstrates a real provider start despite zero typed allowance. Hold renewal changes only owned progress-lock metadata; no other life becomes writable, and closed departure preserves originals and verifies release.

The protected New factory takes only a Runtime in existing server adapters. `new-policy-profile.luau` therefore inherits the ordinary/lifecycle lane in its constructor, copying caller options and rejecting a conflicting lane. Profile checks that the returned factory worker retained the lane before invoking begin. A custom factory that does not support it is refused; it cannot silently choose an untyped worker. Existing factories can retain their CPU-work settings. This does not implement the subsequent replacement account epoch.
