Current application callbacks are real SpiderClient code, exercised with its real menu, frame loop, local stores and world adoption. The server/client protocol and persistence workers still use the private adapter cohort. Ordinary engine startup does not call installRecovery; Persistence.server has no owner factory. Do not describe this as a released recovery feature.

Before enabling normal recovery:

1. Wire protected New Life retirement through the existing retire/prepareFresh/replaceFresh barriers. The current fresh menu explicitly labels protected New as **without saving**, and its actual server decision stays session-only without a credential. This is an interim refusal, not completion of that policy. The original archive and import proposal must remain untouched. A new intent may carry the displayed offer ID; Profile.valid now accepts that shape instead of leaving it indefinitely at Saving.
2. Route subsequent menu choices from a recovered, playing world through a paused, acknowledged session replacement before offering fresh choices. Do not reuse an old offer ID or silently choose a slot after replacement. Cover current and legacy protected slots, local rests and ordinary empty slots.
3. Measure canonical payload sizes and actual loading/transport costs. CLI frame profiling and synthetic clocks do not prove Roblox throughput or FPS.
4. Exercise the actual application path in an unbound native Studio model with memory-backed storage and real RemoteEvents. The private overlay contains 40 candidates, including **two replacements** for production WorldMap and Checkpoint; it adds 38 modules. With 224 current production scripts and two injected diagnostic scripts, that model should contain 264 scripts, of which 222 remain byte-exact production. Record every fingerprint and label the two overrides. Do not call it a fully production-only model.
5. For that native fixture, keep ordinary Persistence disabled and require Studio + PlaceId0. Supply synthetic legacy source records and pristine server templates. Coordinate a separate diagnostic-ready remote so the normal save remotes are not published until the application hook installs; installRecovery deliberately refuses rebinding a started transport. Use the production pause/menu/error callbacks and actual replacement adapters. Verify early exit, matched grant, adoption failure, old packet delivery, exact owner closure, fresh menu hold and immutable archives. Stop/save/close the diagnostic model and preserve original bytes.
6. Then verify a new synthetic key in the isolated test store, including actual leave/rejoin. Never use a player's real save for destructive/fault tests. Follow with natural lifecycle, physical controller/comfort/audio and sustained performance checks, then the release audit and synchronization.

The default 78-suite platform run includes 23 coordinator checks but does not install the private application path. The 31-group private run does install it over actual game code in the CLI shim. Current native whole-application and online-save evidence is still missing. Keep these scopes separate.
