# Private terminal-held lease maintenance

Cancelled/refused recovery deliberately keeps ordinary P/R writes blocked. Previously, leaving that terminal owner at the menu also stopped lease renewal. The counterexample drives the actual old terminal owner past 120 seconds, then lets a second actual SaveSession acquire its expired lease. A generic worker must not be restarted to solve this: its stale whole-progress snapshot could undo recovered choices.

`RecoveryIdlePrototype` now maintains only the existing fresh progress lease. It first probes P uncached, then renews lock metadata approximately twice a minute under the same ten-request rolling allowance. Payload, checksum, timestamp, backup, session marker, R/M1/A1 bytes, local progress and the held pre-recovery baseline remain unchanged. No ordinary write permit escapes the scoped call. It never restarts the cancelled transaction, resets that transaction's 96-request/900-second budget or grants gameplay authority.

A lost renewal acknowledgement requires an uncached probe before another update. Callback replay resets the expected result and recomputes from current storage. Expired, future-dated, foreign, corrupt, newer, unsupported or replaced scopes are fenced; no expired own lease is silently reacquired. Once ownership is lost, the pipeline refuses further accepted recovery in that same owner and reports that a fresh session is needed. It retains local progress and the write barrier. This primitive does not implement a complete session-replacement/import protocol.

An explicit new valid selection stops the idle owner before resuming the actual recovery pipeline. Departure closes intake, stops maintenance and drains its in-flight provider before using the separately verified final three-way progress writer. A second maintenance owner cannot be admitted; active provider calls serialize recovery admission. Local menu changes remain unsaved in memory while held, then persist through the departure/recovery rebind path. Idle metadata renewal itself does not claim those changes were saved.

## Slow acknowledgement correction

The added latency regression fails the initial implementation: a provider runs its still-valid renewal callback later, commits a new beat, then returns after the previous beat's expiry. Judging that answer only against the old beat falsely loses a healthy owner. The corrected callback bounds uncertainty by its candidate's new beat, still requiring an exact positive acknowledgement or a fresh uncached probe. It does not extend the remote lease on a guess. The initial module and failed output are retained as `before-latency-fix-*` and `idle-latency-baseline-*`.

## Evidence

The combined current-source cohort passes **14,134 idle assertions + 24,648 preceding recovery/departure regressions = 38,782 checks**, entry compilation and full strict analysis with all 24 private candidates. Four healthy cancelled/refused, pre/post-rest fixtures each wait eight simulated minutes; they retain fresh leases with about two renewals per minute and byte-identical payloads/other keys. Tests also exercise actual discovery/selection/pipeline retry, departure and subsequent global-progress load, shared quota exhaustion, lost acknowledgements/read failures/exceptions, callback replay, changed identities, stale/foreign leases, coroutine isolation and slow acknowledgement timing.

The guarded Studio server fixture separately passes **22 assertions**, with all **245 script fingerprints** matched and no CreatorErrors between guard and pass. All project executable scripts except the probe are disabled; its backend is MemoryBackend. It uses controlled terminal metadata around actual SaveSession, baseline, pipeline object, idle and departure helpers. It does not execute the full discovery/archive/schema-3 pipeline natively, read actual DataStores, prove real rejoin durability, play a natural life or measure frame rate. `recovery-idle-native-receipt.json` and the corresponding selected events bind that scope.

The initial Studio fixture stopped at an overly broad all-DataModel executable check before testing the helpers. A read-only server listing identified engine-added ChatScript/BubbleChat/ChatServiceRunner, PlayerScriptsLoader, RbxCharacterSounds and Studio Freecam scripts. The corrected runtime assertion checks the same four project folders as the unchanged pre-Play source/disabled guard. Initial manifest/probe/events remain under `initial-*`; neither diagnostic was published. Both sessions were stopped/closed and their original packages retained unchanged.
