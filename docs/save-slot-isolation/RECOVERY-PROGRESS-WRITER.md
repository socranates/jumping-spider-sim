# Private global-progress absorption

This module absorbs the immutable recovered-rest progress proposal into the latest supported P primary. It never allocates a rare-life serial, rewrites M1/R/A1 or grants gameplay authority. The migration remains disconnected from production.

## Merge and replay rules

`Projection.mergePending` reuses the existing closed-field, settings/schema-1 mapping and capacity checks. It recomputes the merge from the current P value inside every UpdateAsync callback invocation, rather than publishing the stale progress snapshot prepared before the rest replacement. Notebook pages retain stored-first union order; eye time, completion/intro/window flags and rare serial/claims/once/blocked marks merge monotonically. Page and rare-map unions beyond their supported cardinalities refuse before the ordinary merge could truncate them. Unsupported fields or changed/dropped settings refuse without a write. The proposed packet's 32K canonical progress budget and existing node/depth bounds still apply.

Newer stored appearance/settings win. When timestamps are equal, current stored choices also win, with missing keys supplied by the proposal. This differs deliberately from ordinary live-session incoming-wins ties: an old migration must not replay over a later setting changed within the same coarse clock tick. A retained counterexample using ordinary incoming-wins ties fails the current/equal-time choices test. Writes use max(current timestamp, proposal timestamp), never wall-clock now; an unchanged merge at an older timestamp advances that timestamp once so replay has a stable comparison basis.

Once the proposal is covered at an equal/newer timestamp, the callback makes no write. Later monotonic observations survive subsequent replays. Global absorption does not require a new outer-envelope receipt that normal P writers would silently discard: the pending proposal remains recoverable in R/M1, and the current P is checked semantically. No pending data is removed by this module.

## Protocol and lease boundary

Pure preparation validates the full packet and owns/freezes the small proposal/opaque anchor in a registered private handle. Begin requires that handle and a synchronous revocation fence. Each job verifies exact M1 raw readback and the exact selected encoded R target before attempting P. Its callback accepts only a known supported primary envelope with the current session's unexpired lock, checks the clock on every callback invocation, and recomputes against that latest payload. It never takes over an absent/expired/foreign lock or defaults a missing/unreadable primary. Unknown envelope/lock protocol fields refuse. A changed write retains the prior good P primary as the normal envelope backup, preserves lock metadata and does not refresh the heartbeat or elevate choice timestamps to now.

Both successful and ambiguous acknowledgements require uncached raw P readback. Readback must still have a fresh owned lease and semantically cover the proposal at an equal/newer timestamp before `globalVerified`. An unabsorbed proposal requires explicit caller backoff/retry; failed reads are not absence. Revocation, cancellation and callback replay after lease takeover refuse. Each step uses at most one request; a controller must supply scheduling, heartbeat priority and overall request/deadline bounds. Backend calls are prohibited within cooperative preparation.

This is not a multi-key atomic transaction. R can change after its verification read, and the P lock can change after a P readback. `globalVerified` describes this component's verified observation and grants no life/write authority. Future controller integration must define durable accepted intent, serialize ordinary writes, revalidate selected R and session/lease state before entry, preserve pending proposals through later saves, and test cross-session interruption/takeover paths. A local fence alone is not a remote lease proof.
