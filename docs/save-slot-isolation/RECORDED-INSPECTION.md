# Recorded-world inspection prototype

Sourceccc0abb, private only. The new inspector validates a Test Garden checkpoint against its explicitly recorded map without changing WorldMap.use, live roots, checkpoint bytes or ordinary Continue/restore admission. It returns a separate owned decoded graph; it does not expose a commit through this API. Production Checkpoint and WorldMap remain unchanged.

The generated world-3 fixture includes bed_a flies and woodlice, shared feeding/needs objects, a rest under the bed's stone and an earned growth stage.33 assertions pass: source bounds/retreat/schema refusal, unknown world/revision/seed refusal, decoded object ownership, cross-root aliases, retained growth, unchanged source/live state,11 cooperative suspensions and cancellation. Ordinary Checkpoint.check/prepare still refuse the incompatible ecology under the Preserve. Both private modules compile and full strict analysis passes in a disposable source tree. This is a generated compatibility fixture, not an imported player's historical save or a native/durable migration test.

Files: make-recorded-inspection.py generates exact candidates and their original/candidate hashes; run-recorded-inspection.py injects them into the CLI bundle without production edits; check-recorded-inspection.py analyzes a disposable copy. The inspection receipt and type logs preserve results. Supported maps are only currently authored world-3/preserve-3 identities. Older geometry and unknown revisions are not guessed. Callers must still bound/validate the containing save envelope before using this private lower-level API.

The policy remains: import portable spider progress into the Preserve and keep the entire original save unchanged in an archive. Inspection alone must not be wired into ordinary Continue: the old ecology would otherwise be applied to the destination. Before production integration, implement the bounded archive and explicit portable projection together, preserve complete original progress/rest/backup envelopes, keep source authority/lease/intent fences, and verify destination recapture without duplicate feeding or archive growth. Refer to migration-design.md for fields and limits. No migration or archive is implemented by this prototype; no live save is read or written.
