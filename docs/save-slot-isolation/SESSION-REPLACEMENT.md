# Explicit session replacement

Private adapters over the actual SaveService, SaveClient and SaveContinuation, on production source `8c9b71896736d85d43e02fec1521bcd567cdb33f`. No production hook, menu change or publication is made by these files. Existing completed production qualification and the candidate remain in `docs/restored-slot-ownership/`.

The preceding all-slot owner could safely hold a changed choice after accepted migration writes, but could not complete that mode change in the same visit. Replacement now has an explicit optional protocol. First compatible hello freezes capability; older peers cannot upgrade through a later hello. A fresh session does not automatically select or restore a life. It presents fresh offers for another explicit choice.

The four modules are:

- `replacement-protocol-prototype.luau`: bounded control shapes, tokens, version, five-second retry gap and 120-second transition deadline.
- `replacement-owner-prototype.luau`: adds intake quiescence and exact closed-departure proof to the all-slot owner. It revokes old decisions, cancels recovery/save work and maintains the enforcing hold. New owners can inherit ordinary request debt before their first load.
- `replacement-service-prototype.luau`: wraps the real service, including its actual add/remove/load/shutdown paths. Only a verified old departure can lead to a new owner. The physical account key is retained. Recent ordinary request debt is carried into the new scheduler; the adapter waits for room for the four initial load requests. An attached startup lane is closed on replacement. Departure retains its existing bounded emergency allowance. Control retries do not repeat an old flush or create duplicate owners.
- `replacement-client-prototype.luau`: wraps the real client and continuation. Application pause and fresh-menu callbacks are mandatory. Old offers, requests, rest preparation and recovery receipts are invalidated before any pause callback can yield. Outbound updates retain a coroutine-local transport generation so a suspended old progress build cannot later be stamped with the new epoch. A matching nonce-bearing fresh loaded reply constructs a new continuation. Callback refusal, timeout, failed departure or failed construction stays read-only.

The exchange is request → offer → ACK → verified old departure → commit → ready → nonce-bound new loaded. The commit is sent under the old epoch and does not itself open the new session. Every ordinary client message from a negotiated peer is bound to its current epoch. Initial compatible negotiation and idempotent ready retries are the only bounded handshake exceptions. Late old grants, receipts, intents and progress cannot authorize the new session.

The request carries a bounded sanitized final notebook/settings/progress snapshot. The old owner merges it before closing intake; the existing departure performs its actual three-way merge and uncached readback. Stored R, immutable A1 and existing M1 are retained. Unconfirmed checkpoint candidates are revoked, not relabelled as stored; the application must retain any desired local checkpoint separately. This is not a rollback claim.

The constructor adapter detects a cooperative fresh factory that outlives its player, discards its unloaded owner without storage I/O, and cannot revive a removed player. Removal/shutdown while the closing UpdateAsync yields uses the real service's existing single departure count. A fresh factory failure also cannot reopen the old world. General initial-visit factory cancellation, actual application pause/menu ownership and native lifetime behavior still require activation review; this fixture's replacement callbacks are scripted booleans, not a native game menu.

Tests in `replacement-tests.luau` cover all three selected modes, exact old closure, final progress, unchanged other durable records, old epoch replay, stale prepared work, loss of every control-message kind and the new loaded reply, wrong nonce/shape, a suspended old client progress build, refused pause/menu callbacks, failed persistence, consecutive replacements/imports, timeout with healthy lease maintenance, removal and shutdown during closure, constructor failure/cancellation and a changing keyOf function. The request ledger asserts the rolling ordinary allowance across sessions, with the established departure exception. Synthetic clocks, memory-backed DataStore adapters and opaque compression fixtures are used. These are not measured loading times, real network timing or online persistence proof.
