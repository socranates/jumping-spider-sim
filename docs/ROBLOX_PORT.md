## Port order

1. **Foundation (this chunk):** appearance table, first spider, basic touch/gamepad input, pure checks and Studio runner. Finish physical-controller/tablet feel and camera/edge acceptance before calling controls complete.
2. **Core silk implemented; recommended Claude chunk: recovery camera and control acceptance.** Port capped catch framing/collision/player takeover, device-aware prompts and recovery scenarios. See HANDOFF-roblox-silk.md. Preserve jump/silk rules; finish physical-device and ten-miss acceptance before claiming full recovery parity.
3. **Perception:** observation/association/memory first, then cone, peripheral cues, Focus and UI. Build transparent golden fixtures for occlusion/identity boundaries. Prototype eye rendering separately.
4. **Flies:** decision logic and perches, senses, locomotion/flight, capture/struggle/feeding, energy and vent replenishment. Integrate shared clock and accessible controls as each action arrives.
5. **LIFE and wasp:** clock/hunger/rest, stages/moults and drawn growth/softness, warning/predator, death/continuing/modes, notebook and menus.
6. **Persistence:** server-owned versioned DataStoreService saves once LIFE state has a stable schema. Preserve last-rest/notebook/unlock semantics, retry/failure feedback and incompatible-record protection. Test with an isolated test experience/store, never production saves.

Accessibility, device checks and golden tests accompany each chunk; they are not a final cleanup phase.

## Server and platform rules

- **Solo servers first:** publish with maximum players = 1, giving each player a separate server/windowsill. This is the chosen initial architecture; no shared play is authorized in this chunk. Current client-only spider is prototype state, not authoritative multiplayer. Publication settings have **not** been configured by this local build. Before saved progression, move authoritative LIFE/award decisions to the server and validate client requests.
- No custom typed text exists yet. Any future spider name or other player text must be filtered on the server with TextService and the correct recipient/broadcast result before display or reuse. Built-in chat uses Roblox's chat system; do not replace it with a raw echo.
- Saves use DataStoreService, not client files. Do not enable production Studio API access to test saves.
- Keep anchored parts moved with BulkMoveTo. The Studio test caps the current rig at 160 parts. This is a budget check, not a mobile-performance pass. Measure frame intervals on a real low-end phone/tablet with settings/device recorded, without screenshot stalls; report median/p95/worst and warm-up separately. Reduce decoration/postprocessing based on evidence.

## Testing workflow

From `roblox_port/`, run `python tests/run.py path/to/luau` (Luau 0.742 used here). Original 35 jump/support checks use the Godot-exported `tests/jump_reference.json` / `.luau`; eight foundation checks cover appearance/input. The current suite is 115/115 with tether goldens and release/reel checks. Extend this pattern for each pure module. Export new fixture data from the frozen Godot implementation, record source commit and parameters, and retain both expected decisions and numeric tolerances. Never regenerate expected values from the port under test.

Run `python tools/build.py path/to/rojo` (Rojo 7.7.1 here). It stamps a source/test/project SHA-256 prefix in BuildInfo and rebuilds both places. Open **TheWindowsillTests.rbxlx** in Studio and press Play. `ServerScriptService.PortTests` runs real Vector3, raycasts, parts and BulkMoveTo, emits `PORT_TEST_REPORT` JSON in Output, and stores it as `TestService.PortTestReport`. The count includes a suite-completion check; a missing report is not a pass. Save the JSON with the evidence ID. Normal TheWindowsill.rbxlx excludes the test runner. This lightweight pcall runner is intentionally dependency-free; extend it or adopt TestEZ as suites grow.

Engine-dependent tests run inside Studio on Windows; the plain Luau CLI cannot validate Roblox engine behavior. Linux collaborators can run pure tests. Nathan's PC/tablet playtest covers feel beyond either automated suite. Do not label emulation as physical-device testing.

Current evidence: [roblox-silk/RESULTS.md](verification/roblox-silk/RESULTS.md): 115 pure, 18 Studio (two completion rows), 3 scripted actual-client checks. Collect per-row reports with tools/collect_studio_report.py to avoid log truncation; the client playback is excluded from the normal place. Godot's 644/644 Linux report `87c44d9c8206` is inherited evidence, not a new Windows run or Roblox test count.
