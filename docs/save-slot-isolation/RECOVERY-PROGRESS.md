# Private global progress projection and rare-life binding

This preparer joins the current supported progress primary, the current session's owned progress observation, and the selected portable-life capsule. It returns owned/frozen progress plus a bound life capsule and a proposed identity descriptor. It makes no backend call, changes no input, calls no New Life/Fresh routine and grants no write or life authority. The global/checkpoint pair still needs an idempotent durable transaction.

## Supported mapping and preservation

Notebook pages are a unique union in stored-first order, eye time takes the maximum, and finished-main/intro-seen/hut-window flags remain monotonic. Appearance and settings follow the existing timestamp/tie rule, independently per setting with older values retained where newer progress has none. Well-formed unknown notebook page/appearance ids retain their data, as SaveProgress already specifies; this component does not prove that a current renderer can display an unknown appearance. `recovery-progress-fields.json` enumerates the supported top-level mapping.

Schema-1 supported `prefs` move to settings through the known migration and are checked against the envelope's actual migration result. Duplicate page ids normalize as set membership, and explicit false optional monotonic flags mean absent/false. These are defined semantic normalizations; the complete original storable values remain unchanged in the archive, including the backup. Settings that would be dropped, clamped or changed refuse here. Unknown top-level/notebook/rare fields, newer settings/schema data, invalid values and unreadable primaries also refuse rather than inventing a default or silently selecting a backup. Backup selection is an explicit future recovery policy; a valid primary's backup remains archived, not silently merged into active choices.

The ordinary progress merge can trim a notebook union beyond 200 pages and rare unions beyond 64 claims/once entries (marking rare history blocked to prevent repeat encounters). The migration preparer checks those unions before merge and refuses overflow. A recorded visit that would add an over-cap claim also refuses. This preserves all portable entries or produces no result; it does not replace the broader goal with a smaller truncated history. Supporting larger histories will require an explicit schema/storage extension. No user data is deleted by refusal.

## Rare binding

Rare ledger high-water serials/claims/once flags and blocked status merge monotonically. A selected life with an existing matching-generation rare serial keeps that serial even when the global ledger has advanced beyond it. A known saved visit supplies claim evidence if the progress ledger lagged behind that rest; an existing higher claim is never lowered. The actual RareDirector test restores a recorded visit as that same animal and prevents a rewound life scheduling an already claimed animal again.

A legacy rest with no rare identity uses the existing high-water serial, or a proposed first serial of 1 when no high-water mark exists, matching current legacy ensureLife behavior. Preparation does not increment the live ledger or allocate another roll on retry. The bound capsule records the serial/generation/birth day before destination assembly. The proposed binding key includes archive identity, slot, persisted source life token and generation with length framing. This key and the source checksum are descriptors, not authentication or ownership proof.

A source whose rare generation disagrees with its lineage generation refuses until the durable protocol can explicitly bind that new generation once. Arbitrarily incrementing on every preparation could reroll after a partial write. The same source observations produce the same candidate; this does not establish idempotence across changing global observations or interrupted multi-key commits. The future transaction must persist and recover its chosen binding rather than recomputing from partially written progress. Source seed handling and global/life identity must remain bound throughout that transaction.

## Evidence and remaining work

The current bundle passes 62 global-progress checks, 21 cooperative suspensions, and the preceding 72 destination/360 life/49 meal checks. It covers supported schema-1 preferences, notebook/choice/flag merges, timestamps, capacity counterexamples, unknown-field/settings refusal, corrupt/newer/missing primary refusal, source immutability, deterministic preparation, cancellation, rare rewind/high-water/visit behavior and global-to-destination identity composition. The joined checkpoint is accepted by the production validator bodies. The rich authored-ecology fixture remains in the destination suite; the extra global binding composition uses a fresh home template and is not a second streaming/playability claim.

Compilation and full strict analysis pass with all six private modules in a disposable source tree. An initial strict failure from an optional envelope payload type was retained and corrected with an explicit nil guard. `verify-recovery-progress.py` reconstructs the executed bundle from current production/private inputs and checks source/output/type hashes and the field inventory.

Composition also exposed an ended-life edge case in the private destination builder: it accepted an ended-life capsule as an ordinary rest, while normal checkpoint restore clears lifeOver. The retained pre-fix builder fails the new regression. It now refuses that case until ending-specific recovery exists. This is a private importer fix, not evidence of a published gameplay regression. Its corrected destination cohort is 72 checks; prior 71-check evidence is retained as historical.

The components remain outside production. Still needed: explicit provenance/binding schema and lifetime rules; archive-ready/global/rest commit and readback/restart protocol; real source/owner/intent fences at final commit; actual legacy offers; source-seed policy; generation-mismatch binding and ended/mating/hatching entry handling; native transport and real isolated DataStore/rejoin tests; release/main/publication/laptop synchronization. Existing game source and normal Continue protections remain unchanged.
